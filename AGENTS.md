# LabFlow AI

A voice first lab notebook: dictate a measurement, confirm what LabFlow understood, get a table, a chart, and answers with no invented numbers.

## Stack

- **Web** (`web/`): TypeScript strict, Next.js 16 App Router, Tailwind CSS, TanStack Query, Plotly (browser only). pnpm.
- **API** (`api/`): Python 3.13, FastAPI, SQLModel + Alembic on Supabase Postgres, pydantic-settings. uv.
- **AI**: Ollama Cloud first, Claude (`claude-opus-5-5`) as automatic fallback, behind one `LLMProvider` interface. ElevenLabs Scribe for speech to text.
- **Contract**: Pydantic models are the source of truth; `make openapi` writes `api/openapi.json` and `web/src/api/schema.d.ts` (both committed). The browser only calls `/api/*` on its own origin; Next.js rewrites it to FastAPI.
- **Hosting**: Vercel (web), Railway (api). Full decision: [spec 0001](docs/specs/0001-stack-architecture/index.md).

## Build approach

Skateboard: ship the smallest usable notebook first (typed capture with confirmation), then grow it release by release.

## Specs

Stored in `docs/specs/`, one folder per decision: `docs/specs/NNNN-title/index.md` (plus `verify.md`). Scope lives in `docs/scope/scope.md`.

## Rules

- Functional style: functions are pure by default; I/O (DB, LLM, ElevenLabs, fetch) stays at the edges (FastAPI routers and dependencies, React hooks and query functions) and is explicit.
- Data is immutable: `const` and `readonly` in TS, frozen Pydantic models or new copies in Python. No module level mutable state, only constants.
- Prefer plain functions and composition over classes. Exception: the `LLMProvider` interface and SQLModel tables.
- Expected failures are explicit return values (a result union in TS, a typed result in Python), not exceptions. Exceptions are for bugs and are turned into HTTP errors only at the router edge.
- One API error shape everywhere: `{"code": "<snake_case>", "message": "<Spanish, shown to the user>"}` with a fitting status. No bare `except`; every LLM fallback is logged.
- Folders by layer: `api/app/{routers,models,services,repositories,core}/` (`repositories/` holds the DB I/O, spec 0002), `web/src/{app,components,hooks,api,lib}/`.
- Types are strict: TS `strict`, no `any`; every Python function fully type hinted and checked by pyright in strict mode.
- Env is validated at startup: `api/app/core/settings.py` fails fast on a missing key; `web/next.config.ts` refuses a production build without `API_URL`. Secrets never get a `NEXT_PUBLIC_` prefix.
- Named exports only in `web/`, except files Next.js needs as default exports (`page`, `layout`, `route`, `next.config`, and similar).
- Conventional commits: `feat:`, `fix:`, `docs:`, `test:`, `chore:`, `refactor:`.

## Tooling

Chosen here; `/develop tooling` installs it.
- Lint and format: ESLint (installed) + Prettier in `web/`; Ruff (lint + format) and pyright (strict) in `api/`.
- Pre commit: lefthook runs format, lint and typecheck on staged files in both apps.
- Tests: pytest + FastAPI `TestClient` (api), Vitest + Testing Library (web). A feature is done with unit and integration tests for its main path and error states.
- CI: GitHub Actions on PRs and `main`: lint, typecheck and tests for `web/` and `api/`.
